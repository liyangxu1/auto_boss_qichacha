# 本机求职工作台

访问地址为 http://127.0.0.1:8765，只监听本机。沿用现有 Conda AutoBOSS、已有 Chrome 和根目录 .env，不创建新环境。首次运行前端已经构建，日常启动不需要 Node。

```sh
conda activate AutoBOSS
python main.py
```

也可以在Python中调用 `from main import start_app; start_app()`。启动器会复用已经运行的服务；首次启动在后台运行，脚本退出后网页仍可访问。仅启动不会采集岗位或调用模型。原来的管理脚本继续可用：

```sh
./scripts/web.sh start
./scripts/web.sh status
./scripts/web.sh stop
```

停止网页服务不会关闭独立的 BOSS 浏览器；手动关闭 BOSS 后，可以再次连接并复用登录。当前没有设置开机启动。

## 页面操作

1. 上传不超过20MB的 PDF。后台依次提取文字、AI解析9类字段、生成搜索建议。扫描图片 PDF 暂不自动OCR，缺少文字时会明确报错。原文引用不符时只修正错误字段，并再次严格核验，不能通过就停止。
2. 查看简历预览，需要修正时编辑 JSON。重复上传相同 PDF 会复用已有解析与该简历偏好，减少重复模型调用；任务提示会注明复用。需要重新调用模型时可请求 POST /api/projects/{id}/parse?fresh=true。
3. 调整求职方向、城市、经验筛选和关键词。关键词可添加、删除、前移，按保存后的顺序单独搜索。用户指定的 Agent / AI 应用方向优先于原简历标题。城市只使用明确求职意向或用户补充，不根据学校和现居地猜测。
4. 点击连接 BOSS。网页与命令行统一复用 data/browser/boss，已有登录先检查，不另建空白登录目录。浏览器目录被其他进程占用时停止，不复制或强行解锁活动目录。
5. 保存条件并开始搜索。默认每个关键词6个、本轮36个，可在“经验说明与采集数量”调整。网页不会自动混入扩展关键词或经验不限。采集只访问岗位、公司，实时保存 JSON 列表；暂停和停止在当前岗位完成后生效，窗口保留。默认全职偏好，明确的兼职和实习保留在历史库中，默认隐藏且不参与匹配；没有标注用工类型的岗位需进一步核实。
6. 采集正常完成后自动进入AI匹配，补齐累计岗位中的未分析项并复用有效缓存；停止采集、登录失效或安全验证时不自动匹配。也可点击“匹配待处理岗位”单独补跑。点击评分规则可调整7个维度、权重、评分要点、提示词和最低完整度，权重合计必须为100%。列表按可排序岗位的匹配度从高到低显示；点开岗位查看各维度依据与差距。

网页没有发消息、沟通或投递接口。采集仍使用原有 Python Patchright 流程，只监听页面自然返回的职位详情，不构造私有投递请求。缺失公司资料留空；匿名公司的相同占位名称不跨岗位合并。打开公司主页补充资料是可选项。

## 登录状态

原 get_jobs 在 PlaywrightManager.java 中使用固定 browser-data 持久化上下文，并在登录成功后保存 BOSS Cookie 到数据库，下次启动注入。我们的 Python 版本使用：

- data/browser/boss：同一个 Chrome 专用目录，保存 Cookie、LocalStorage 等浏览器资料。
- data/browser/boss/autoboss-auth/state.json：本站 Cookie 和 LocalStorage 的额外备份，只在原目录没有可用登录凭证时恢复，不覆盖已有凭证。
- metadata.json：上次保存时间，不含凭证正文。备份目录权限700、文件600，整个 data 被 Git 忽略，不通过 HTTP 返回凭证。

网页登录成功和运行过程中每60秒保存一次本地快照，这只是本地保存，不是向 BOSS 定时发请求。不会篡改 Cookie 有效期或绕过安全验证。Cookie存在不等于服务器认可登录，以实际页面为准。BOSS 服务端过期、主动退出或要求验证时仍需要人工处理，无法保证永久免登录。

## 评分方式

模型只分析逐项事实，不计算总分。代码逐项核验简历 JSON Pointer 引用和原文摘录；无证据或引用不符的维度为待确认，不按零分处理。

匹配度 = Σ(已知维度权重 × 该维度分数 / 5) ÷ 已知维度权重之和 × 100。

信息完整度 = 已知维度权重之和。默认达到70%才参与优先排序；不足的岗位仍展示分析，排在信息充分岗位之后。该分数表达当前规则下的适配程度，不是录用概率。全职和实习分开，姓名、联系方式、年龄和性别不参与匹配。

缓存键包含简历业务信息、岗位及公司内容、个人偏好、评分规则和模型名称和分析日期。明确区分能力差距与需要确认的问题，存在未解决冲突的维度不计分；传入当前日期，避免把已过去的工作日期误认为未来。任一内容改变后，旧分数不再显示，重新匹配会使用新缓存键。

默认权重为岗位方向20%、核心技能20%、项目经历20%、相关经验15%、学历要求15%、公司业务5%、个人偏好5%。仅修改权重或最低完整度时，立即复用已经核验证据的分析重算总分；修改评分要点、提示词或维度结构仍需重新调用模型。缺失或冲突的学历信息会降低信息完整度，不伪造为符合条件。

采集和匹配属于同一个后台流程的两个阶段，中间不释放当前简历的任务锁。阶段切换时页面显示匹配进度并撤去采集暂停入口。失败岗位保持待匹配，具体错误保存于该简历目录的 match-errors.json，包含错误分类、字段路径和底层异常类型，不记录密钥与简历原文。再次匹配复用有效缓存，补齐尚未成功的岗位。

当前TokenPony兼容接口使用OPENAI_STREAM=true、OPENAI_ENABLE_THINKING=false、OPENAI_MAX_OUTPUT_TOKENS=8192、OPENAI_TEMPERATURE=0。流式响应只合并正文，思考内容不保存；只有完整结束且通过字段、维度和原文证据校验后才保存评分。字段结构错误只定向修正一次，网络失败和超时不自动重发。默认保持模型原有代理设置；必要时OPENAI_DIRECT=true只让模型请求直连，其他应用及系统代理不变。其他服务不支持这些兼容选项时应关闭或留空。

## 代码结构与数据

- frontend/src：React页面，按搜索面板、岗位列表、详情面板、规则/简历编辑器拆分。
- autoboss/web/app.py：本机API、输入校验、PDF上传及静态页面服务。
- autoboss/web/workflows.py：连接现有解析、搜索、采集、匹配服务。
- autoboss/web/tasks.py：后台任务与落盘进度，同一份简历串行执行。
- autoboss/web/browser_worker.py：唯一持有浏览器的进程，串行消费本地命令，采集结束后继续维持窗口。
- autoboss/boss/auth.py：登录资料保存与恢复；网络隔离继续复用 boss/network.py。
- autoboss/matching：评分规则、证据校验、加权计算和版本缓存。
- autoboss/web/static：已构建的前端，Python直接提供，不需要另起Vite。
- data/web/projects/{id}：原PDF、提取文字、9字段简历、搜索条件、规则、匹配缓存及 runs/{id}/jobs.json、companies.json、run.json。
- data/web/tasks：任务状态；data/web/server.log：服务日志；data/web/browser/worker.log：浏览器日志。

岗位库合并本项目全部历史采集和所有简历项目的采集批次，按BOSS岗位链接去重，累计保存到 data/web/catalog/jobs.json，保留首次和最近采集时间及来源批次。新采集不会覆盖历史列表；同名匿名公司不会跨岗位合并。匹配结果仍按当前简历、偏好和规则隔离，最多同时分析2个岗位。勾选“显示已过滤岗位”可查看兼职和实习原始记录，导出跟随此选项。服务重启后保留结果，执行中的非持久后台任务标记中断，可手动重做；浏览器独立运行。

AI使用 .env 中配置的服务，简历解析会将提取的文字发给该服务；搜索和匹配会排除姓名及联系方式。BOSS使用专用直连子进程，Codex和模型的代理保持原样。Clash开启TUN时会明确停止采集，需要先采用能区分直连的网络设置，不擅自修改系统代理。

前端开发和构建（仅在修改页面时需要）：

```sh
cd frontend
npm ci
npm run build
```

已有环境缺少依赖时，应先检查环境，不要在启动脚本里安装。当前新增FastAPI、Uvicorn、python-multipart，其余复用原环境。前端依赖锁定在package-lock.json中。
